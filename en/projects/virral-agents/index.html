Problem → solution

Problem

Conversations with models from different vendors are scattered across many services, each keeping your history. A model with internet access decides on its own what to fetch and when.

Solution

One panel on your own server with your own keys: OVH, Z.ai, OpenAI, Anthropic, Gemini, OpenRouter. Messages are encrypted in the database, and web search goes through an MCP server only after approval of the specific query.

Three engineering decisions

  1. 1
    Approval first, internet secondThe model can only suggest a search. The app runs it after the user clicks (ASK mode), so you know what went out to the web and when.
  2. 2
    Encrypt before savingMessage content, titles, images and emails are encrypted; session tokens are stored as hashes. A database leak doesn't expose conversations.
  3. 3
    Thin controllers, logic in servicesA controller takes the request and returns the response; authorisation lives in middleware, the rest in services. Each AI provider is switched on by a key in the environment.
